Guía de Despliegue — Nexo SaaS en AWS

Infraestructura Free Tier  ·  Sin terminal, 100% interfaz visual
EC2 t2.micro + ECS + RDS PostgreSQL + GitHub Actions (CI/CD automático)
Costo estimado: $0/mes (primeros 12 meses de cuenta AWS nueva)

¿Qué hace esta guía?
Despliega toda la aplicación Nexo en AWS usando solo interfaces visuales: la consola de AWS y la interfaz web de GitHub. Una vez configurado, cada vez que empujes código a GitHub el despliegue ocurre automáticamente, sin tocar ninguna terminal.
¿Qué necesitas antes de empezar?
  • Una cuenta de AWS activa (aws.amazon.com)
  • Tu repositorio de Nexo en GitHub (github.com/krlo-dev/nexo)
  • Tu API Key de NVIDIA NIM (nvapi-…)
  • Una contraseña segura para la base de datos (mínimo 12 caracteres con símbolo. Ej: Nexo2026!!Clave)
  • Un JWT Secret largo (mínimo 32 caracteres. Puedes generar uno en randomkeygen.com → "256-bit WEP Key")
Configura una alerta de costos primero. En la consola AWS ve a Billing → Budgets → Create budget → Zero spend budget. Recibirás un email si algo sale del free tier.

Paso 1 — Crear la infraestructura con CloudFormation

Este paso crea de una sola vez: la red (VPC), la base de datos (RDS), los repositorios de imágenes (ECR), el servidor (EC2) y el orquestador de contenedores (ECS). Todo a partir de un único archivo.

1.1 — Abrir CloudFormation en la consola AWS

  1. Ve a console.aws.amazon.com e inicia sesión.
  2. En la barra de búsqueda superior escribe CloudFormation y presiona Enter.
  3. Verifica que la región (esquina superior derecha) sea US East (N. Virginia) us-east-1. Si no lo es, cámbiala desde ese menú.
  4. Haz clic en el botón naranja Create stack → selecciona With new resources (standard).

1.2 — Subir el archivo del stack

  1. En la sección "Specify template" selecciona Upload a template file.
  2. Haz clic en Choose file y busca el archivo en tu computador: C:\Users\Carlito\Documents\SaaS NEXO\infra\cloudformation.yml
  3. Haz clic en Next.

1.3 — Configurar los parámetros

  1. En el campo Stack name escribe: nexo-prod
  2. Completa los parámetros según la siguiente tabla:
ParámetroQué ponerEjemplo
DBPassword Contraseña para la base de datos (mín. 12 chars con símbolo) Nexo2026!!Clave
JwtSecret Secreto para los tokens de sesión (mín. 32 chars) El valor que generaste en randomkeygen.com
NvidiaApiKey Tu API Key de NVIDIA NIM nvapi-xxxxxxxxxx
NvidiaNimUrl Dejar el valor que ya aparece —
GlmModel Dejar el valor que ya aparece —
EC2InstanceType Dejar t2.micro Free Tier
DBInstanceClass Dejar db.t2.micro Free Tier
AllowSSHFrom Dejar 0.0.0.0/0 —
  1. Haz clic en Next.

1.4 — Opciones del stack

  1. No cambies nada en esta pantalla.
  2. Haz clic en Next.

1.5 — Revisión y confirmación

  1. Baja hasta el final de la página.
  2. Activa la casilla que dice:
    "I acknowledge that AWS CloudFormation might create IAM resources with custom names"
  3. Haz clic en Submit.
Ahora espera entre 8 y 12 minutos. La barra de estado mostrará CREATE_IN_PROGRESS. Cuando cambie a CREATE_COMPLETE (fondo verde) puedes continuar. Puedes ver el progreso en la pestaña "Events" del stack.

1.6 — Guardar los datos de salida (Outputs)

  1. Haz clic en tu stack nexo-prod.
  2. Abre la pestaña Outputs.
  3. Copia y guarda estos valores (los necesitarás más adelante):
Key (nombre)Para qué lo usarás
ElasticIPAddressLa IP pública de tu app — para abrirla en el browser
BackendECRUriURL del repositorio Docker del backend
FrontendECRUriURL del repositorio Docker del frontend
DatabaseEndpointDirección interna de la base de datos

Paso 2 — Asociar la Elastic IP al servidor EC2

La Elastic IP es una dirección pública fija que no cambia aunque el servidor se reinicie. Hay que "pegarla" al servidor manualmente una sola vez.

2.1 — Ir a EC2

  1. En la barra de búsqueda de AWS escribe EC2 y entra.
  2. En el menú izquierdo, bajo "Network & Security", haz clic en Elastic IPs.
  3. Verás una IP listada. Haz clic en ella para seleccionarla.

2.2 — Asociar la IP

  1. Haz clic en el botón Actions → Associate Elastic IP address.
  2. En "Resource type" selecciona Instance.
  3. En el campo "Instance" haz clic y busca nexo-ecs-host. Selecciónala.
  4. Haz clic en Associate.
Listo. Esa IP ahora es la dirección permanente de tu aplicación. Anótala — con ella abrirás Nexo en el browser: http://<tu-elastic-ip>

Paso 3 — Crear credenciales de acceso en AWS (IAM)

GitHub Actions necesita un par de credenciales para poder subir imágenes a ECR y actualizar ECS en tu nombre. Las creas desde la consola de AWS.

3.1 — Ir a IAM

  1. En la barra de búsqueda de AWS escribe IAM y entra.
  2. En el menú izquierdo haz clic en Users.
  3. Haz clic en Create user.

3.2 — Crear el usuario para CI/CD

  1. En "User name" escribe: nexo-deploy
  2. Haz clic en Next.
  3. En la pantalla de permisos, selecciona Attach policies directly.
  4. Busca y activa estas dos políticas:
    • AmazonEC2ContainerRegistryPowerUser — para subir imágenes a ECR
    • AmazonECS_FullAccess — para actualizar el servicio ECS
  5. Haz clic en Next → Create user.

3.3 — Generar las Access Keys

  1. Haz clic en el usuario nexo-deploy que acabas de crear.
  2. Ve a la pestaña Security credentials.
  3. Baja hasta "Access keys" y haz clic en Create access key.
  4. Cuando te pregunte el caso de uso, selecciona Other → Next.
  5. En "Description" escribe: github-actions → Create access key.
  6. Verás dos valores. Cópialos ahora — el Secret solo se muestra una vez:
CampoQué copiar
Access key IDAlgo como AKIAIOSFODNN7EXAMPLE
Secret access keyAlgo como wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
Si cierras esta página sin copiar el Secret Access Key, tendrás que borrarlo y crear uno nuevo. No hay forma de verlo de nuevo.

Paso 4 — Configurar los secretos en GitHub

Aquí le das a GitHub las credenciales para que pueda desplegar en AWS automáticamente cada vez que hagas un push.

4.1 — Ir a los Secrets del repositorio

  1. Ve a tu repositorio en GitHub: github.com/krlo-dev/nexo
  2. Haz clic en la pestaña Settings (la última, con ícono de engranaje).
  3. En el menú izquierdo, expande "Secrets and variables" y haz clic en Actions.
  4. Haz clic en New repository secret.

4.2 — Agregar los 3 secretos uno por uno

Repite el proceso de "New repository secret" para cada uno:

Name (nombre exacto)Secret (valor)
AWS_ACCESS_KEY_ID El Access key ID del Paso 3.3
AWS_SECRET_ACCESS_KEY El Secret access key del Paso 3.3
AWS_REGION us-east-1

Al terminar deberías ver los 3 secretos listados en la sección "Repository secrets".

Con esto GitHub Actions ya tiene todo lo que necesita para desplegar en AWS.

Paso 5 — Primer despliegue (push automático)

El workflow de GitHub Actions ya está incluido en el código del repositorio en .github/workflows/deploy.yml. Se activa automáticamente cada vez que hay un push a la rama develop.

5.1 — Verificar que el workflow existe

  1. Ve a tu repositorio en GitHub.
  2. Haz clic en la pestaña Actions.
  3. Deberías ver el workflow "Deploy to AWS" listado.

5.2 — Disparar el primer despliegue

Haz cualquier push a la rama develop. Puede ser un cambio pequeño, como un espacio en blanco en cualquier archivo. O desde GitHub directamente:

  1. En tu repositorio, ve a cualquier archivo de texto (por ejemplo README.md).
  2. Haz clic en el ícono de lápiz (✏️ Edit).
  3. Agrega un espacio en blanco al final del archivo.
  4. Haz clic en Commit changes → Commit changes.
  5. Asegúrate de que el commit va a la rama develop.

5.3 — Monitorear el despliegue

  1. Ve a la pestaña Actions de tu repositorio.
  2. Verás un nuevo workflow corriendo con el nombre "Deploy to AWS".
  3. Haz clic en él para ver el progreso en tiempo real.
  4. Cada paso aparece con un ✅ verde cuando termina exitosamente.
El workflow hace 3 cosas:
  1. Construye la imagen Docker del backend y la sube a ECR (~3-5 min)
  2. Construye la imagen Docker del frontend y la sube a ECR (~2-3 min)
  3. Le dice a ECS que descargue las nuevas imágenes y reinicie los contenedores
Tiempo total: aproximadamente 8-12 minutos.
Cuando todos los pasos tengan ✅ verde, el despliegue terminó. El backend también inicializa la base de datos automáticamente en su primer arranque.

Paso 6 — Verificar que la app funciona

6.1 — Esperar que ECS lance los contenedores

  1. En la consola AWS ve a ECS (Elastic Container Service).
  2. Haz clic en el cluster nexo-cluster.
  3. Ve a la pestaña Services → haz clic en nexo-app.
  4. Ve a la pestaña Tasks.
  5. Espera a que aparezca una tarea con estado RUNNING (puede tardar 2-3 min tras el despliegue de GitHub Actions).

6.2 — Abrir la aplicación

  1. Abre una nueva pestaña del browser.
  2. Escribe la Elastic IP que guardaste en el Paso 1.6: http://<tu-elastic-ip>
  3. Deberías ver la página de inicio de Nexo.

6.3 — Verificar el backend

  1. En el browser ve a: http://<tu-elastic-ip>/api/health
  2. Debe responder: {"status":"ok"}
Si ves la app y el /api/health responde, el despliegue fue exitoso. La base de datos se inicializó automáticamente en el primer arranque del backend.

¿Algo no funciona? — Ver los logs

  1. En la consola AWS busca CloudWatch.
  2. Ve a Log groups → abre /ecs/nexo.
  3. Ahí verás los logs separados en backend/ y frontend/.
  4. Los errores de arranque del backend aparecen en los primeros mensajes del stream.

Paso 7 — Cómo actualizar la app en el futuro

A partir de ahora, cualquier cambio en el código se despliega automáticamente. No necesitas hacer nada manualmente:

  1. Haz tus cambios en el código.
  2. Sube los cambios a la rama develop (push).
  3. GitHub Actions detecta el push y despliega automáticamente.
  4. En ~10 minutos la nueva versión está en producción.
Puedes monitorear cada despliegue en la pestaña Actions de tu repositorio GitHub. Si el workflow falla, verás una ✗ roja y los logs del error.

⚠ Destruir todo (cuando ya no lo necesites)

Esta acción elimina TODOS los recursos y datos permanentemente. Si necesitas los datos de la base de datos, expórtalos primero desde la consola de RDS (RDS → Tu instancia → Actions → Take snapshot).

Paso A — Vaciar los repositorios ECR

CloudFormation no puede borrar un repositorio ECR si tiene imágenes adentro. Primero vacíalos:

  1. En la consola AWS busca ECR (Elastic Container Registry).
  2. Haz clic en el repositorio nexo-backend.
  3. Selecciona todas las imágenes (activa el checkbox del encabezado).
  4. Haz clic en Delete → confirma.
  5. Repite exactamente lo mismo para el repositorio nexo-frontend.

Paso B — Eliminar el stack de CloudFormation

  1. Ve a CloudFormation en la consola AWS.
  2. Haz clic en el stack nexo-prod.
  3. Haz clic en Delete.
  4. En la ventana de confirmación haz clic en Delete stack.
El proceso tarda unos minutos. Cuando el stack desaparezca de la lista, todo ha sido eliminado: VPC, EC2, RDS, ECS, ECR, Elastic IP — todo. Tu cuenta de AWS queda completamente limpia.
