Guía de Despliegue — Nexo SaaS en AWS

Infraestructura Free Tier  |  EC2 t2.micro + ECS + RDS PostgreSQL
Costo estimado: $0/mes (primeros 12 meses de cuenta AWS nueva)

¿Qué hace esta guía?
Despliega toda la aplicación Nexo en AWS usando CloudFormation. Al terminar tendrás un servidor corriendo en una IP pública fija. Cuando ya no lo necesites, eliminas el stack y AWS borra todo automáticamente.
Leyenda de etiquetas:  Consola AWS = acción en el navegador   Terminal = comandos en Docker Desktop   Free Tier = servicio incluido en capa gratuita

Preparación previa (antes de empezar)

Lo que necesitas instalado en tu PC

  • Docker Desktop — descarga desde docker.com/products/docker-desktop
    Necesario para construir y subir las imágenes de la app.
  • AWS CLI — solo para el login de Docker a ECR (1 comando).
    Descarga desde aws.amazon.com/cli → Installer para Windows.

Lo que necesitas tener a la mano

  • Tu API Key de NVIDIA NIM (empieza por nvapi-)
  • Una contraseña para la base de datos (mínimo 12 caracteres, con mayúsculas, números y símbolo. Ej: Nexo2026!!Clave)
  • Un JWT Secret largo (mínimo 32 caracteres. Puedes generarlo en randomkeygen.com → 256-bit WEP Key)
Configura una alerta de billing primero.
En la consola AWS → Billing → Budgets → Create budget → Zero spend budget. Así te avisa por email si algo sale del free tier.

El archivo CloudFormation

El archivo que subirás a AWS está en tu proyecto en la ruta:

C:\Users\Carlito\Documents\SaaS NEXO\infra\cloudformation.yml

No lo modifiques. Solo lo vas a subir tal cual.

1 Crear el stack con CloudFormation

Consola AWS Free Tier

Este paso crea todo: la red (VPC), la base de datos (RDS), los repositorios de imágenes (ECR), el servidor (EC2) y el orquestador de contenedores (ECS).

  1. Ve a aws.amazon.com/console e inicia sesión.
  2. En la barra de búsqueda superior escribe CloudFormation y haz clic.
  3. Asegúrate de estar en la región correcta (esquina superior derecha). Usa us-east-1 (N. Virginia) — tiene el mayor soporte de free tier.
  4. Haz clic en el botón naranja "Create stack" → "With new resources (standard)".

Pantalla "Specify template"

  1. Selecciona "Upload a template file".
  2. Haz clic en "Choose file" y navega hasta:
    C:\Users\Carlito\Documents\SaaS NEXO\infra\cloudformation.yml
  3. Haz clic en "Next".

Pantalla "Specify stack details"

  1. En Stack name escribe: nexo-prod
  2. Llena los parámetros:
    ParámetroValor a poner
    DBPasswordTu contraseña para la BD (ej: Nexo2026!!Clave)
    JwtSecretTu JWT Secret largo (32+ chars)
    NvidiaApiKeyTu API Key nvapi-...
    NvidiaNimUrlDejar el valor por defecto
    GlmModelDejar el valor por defecto
    EC2InstanceTypet2.micro (free tier)
    DBInstanceClassdb.t2.micro (free tier)
    AllowSSHFrom0.0.0.0/0 (o tu IP pública para más seguridad)
  3. Haz clic en "Next".

Pantalla "Configure stack options"

  1. No cambies nada. Haz clic en "Next".

Pantalla "Review and create"

  1. Baja hasta el final de la página.
  2. Activa la casilla que dice "I acknowledge that AWS CloudFormation might create IAM resources with custom names".
  3. Haz clic en "Submit".
Ahora espera. El stack tardará entre 8 y 12 minutos en crearse (el RDS es lo más lento). Puedes ver el progreso en la pestaña "Events". Cuando el estado diga CREATE_COMPLETE en verde, continúa.

Guardar los valores de salida (Outputs)

  1. Haz clic en tu stack nexo-prod.
  2. Ve a la pestaña "Outputs".
  3. Anota (o deja esta pestaña abierta) los siguientes valores:
    KeyPara qué sirve
    ElasticIPAddressLa IP pública de tu app
    BackendECRUriURL del repo Docker del backend
    FrontendECRUriURL del repo Docker del frontend
    DatabaseEndpointDirección del servidor de base de datos
    ECRLoginCommandComando para autenticarte en ECR

2 Asociar la Elastic IP al servidor EC2

Consola AWS

La Elastic IP es tu dirección pública fija. Hay que "pegarla" al servidor manualmente.

  1. En la consola AWS busca EC2 y entra.
  2. En el menú izquierdo ve a "Instances".
  3. Deberías ver una instancia llamada nexo-ecs-host con estado Running.
  4. Copia su Instance ID (algo como i-0abc123...).
  1. En el menú izquierdo, baja hasta "Elastic IPs" (dentro de "Network & Security").
  2. Verás una IP listada. Haz clic en ella.
  3. Haz clic en el botón "Actions" → "Associate Elastic IP address".
  4. En "Resource type" selecciona Instance.
  5. En "Instance" busca y selecciona nexo-ecs-host.
  6. Haz clic en "Associate".
Listo. Esa IP es ahora la dirección permanente de tu app. Anótala — la usarás para abrir la app en el browser.

3 Configurar AWS CLI (una sola vez)

Terminal

Abre Docker Desktop → haz clic en el ícono de terminal (esquina inferior izquierda) o abre una PowerShell normal en Windows.

  1. Escribe el siguiente comando y presiona Enter: 
    aws configure
  2. Te va a pedir 4 valores uno por uno. Consíguelos en la consola AWS → tu nombre (esquina superior derecha) → Security credentials → Access keys → Create access key:
    CampoQué poner
    AWS Access Key IDEl Access Key de tu cuenta (empieza con AKIA...)
    AWS Secret Access KeyEl Secret Key
    Default region nameus-east-1
    Default output formatjson
Guarda bien tu Access Key y Secret Key. Solo se muestran una vez. Si los pierdes, debes crear unos nuevos.

4 Construir y subir las imágenes Docker a ECR

Terminal   Free Tier — 500MB incluidos

Abre una terminal en la carpeta del proyecto. En PowerShell:

cd "C:\Users\Carlito\Documents\SaaS NEXO"

4.1 — Autenticarse en ECR

Copia el valor de ECRLoginCommand del Output de CloudFormation y ejecútalo. Se ve así:

aws ecr get-login-password --region us-east-1 | docker login --username AWS --password-stdin 123456789012.dkr.ecr.us-east-1.amazonaws.com

Reemplaza 123456789012 con tu número de cuenta AWS (lo ves en el Output).
Si aparece Login Succeeded, continúa.

4.2 — Construir y subir el Backend

Reemplaza TU_BACKEND_ECR_URI con el valor de BackendECRUri del Output:

# Construir la imagen
docker build --platform linux/amd64 -t nexo-backend ./backend

# Etiquetar con la URI de ECR
docker tag nexo-backend:latest TU_BACKEND_ECR_URI:latest

# Subir a ECR
docker push TU_BACKEND_ECR_URI:latest
Ejemplo real: si tu BackendECRUri es 123456789012.dkr.ecr.us-east-1.amazonaws.com/nexo-backend
entonces el tag sería: docker tag nexo-backend:latest 123456789012.dkr.ecr.us-east-1.amazonaws.com/nexo-backend:latest

4.3 — Construir y subir el Frontend

Reemplaza TU_FRONTEND_ECR_URI con el valor de FrontendECRUri:

# Construir la imagen
docker build --platform linux/amd64 -t nexo-frontend ./frontend

# Etiquetar con la URI de ECR
docker tag nexo-frontend:latest TU_FRONTEND_ECR_URI:latest

# Subir a ECR
docker push TU_FRONTEND_ECR_URI:latest
El push puede tardar 3-5 minutos según tu velocidad de internet. Verás una barra de progreso por cada capa de la imagen.

5 Reiniciar el servicio ECS para tomar las imágenes

Consola AWS

Las imágenes ya están en ECR. Ahora hay que decirle a ECS que las descargue y arranque los contenedores.

  1. En la consola AWS busca ECS (Elastic Container Service) y entra.
  2. Haz clic en el cluster nexo-cluster.
  3. Ve a la pestaña "Services".
  4. Haz clic en el servicio nexo-app.
  5. Haz clic en el botón "Update service" (arriba a la derecha).
  6. Activa la casilla "Force new deployment".
  7. Haz clic en "Update".
ECS descargará las imágenes de ECR y lanzará los contenedores. Ve a la pestaña "Tasks" del servicio para ver el progreso. Cuando el task tenga estado RUNNING, continúa. Puede tardar 2-4 minutos.

6 Inicializar la base de datos

Consola AWS

La base de datos está vacía. Hay que crear las tablas corriendo el archivo infra/init.sql. Esto se hace una sola vez.

6.1 — Entrar al contenedor del backend via ECS Exec

  1. En la consola de ECS → nexo-cluster → pestaña "Tasks".
  2. Haz clic en el Task ID (el que está en estado RUNNING).
  3. Baja hasta la sección "Containers".
  4. Expande el contenedor backend.
  5. Haz clic en el botón "Execute command".
  6. En el campo "Command" escribe: sh
  7. Haz clic en "Execute".

Se abrirá una terminal dentro del contenedor. Ahora ejecuta el siguiente bloque para crear las tablas:

psql postgresql://nexo_user:TU_DB_PASSWORD@TU_DB_ENDPOINT/nexo <<'SQL'
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

CREATE TABLE IF NOT EXISTS users (
  id            UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  email         VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  role          VARCHAR(20) NOT NULL CHECK (role IN ('admin','emprendedor','cliente')),
  full_name     VARCHAR(255) NOT NULL,
  avatar_url    TEXT,
  created_at    TIMESTAMPTZ DEFAULT NOW(),
  updated_at    TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS stores (
  id               UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  owner_id         UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  slug             VARCHAR(100) UNIQUE NOT NULL,
  name             VARCHAR(255) NOT NULL,
  description      TEXT,
  category         VARCHAR(100) NOT NULL,
  tags             TEXT[],
  avatar_url       TEXT,
  banner_url       TEXT,
  address          TEXT,
  city             VARCHAR(100),
  lat              DECIMAL(10,8),
  lon              DECIMAL(11,8),
  phone            VARCHAR(20),
  instagram_handle VARCHAR(100),
  is_active        BOOLEAN DEFAULT true,
  avg_rating       DECIMAL(3,2) DEFAULT 0,
  total_reviews    INTEGER DEFAULT 0,
  embedding        TEXT,
  created_at       TIMESTAMPTZ DEFAULT NOW(),
  updated_at       TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS services (
  id               UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  store_id         UUID NOT NULL REFERENCES stores(id) ON DELETE CASCADE,
  name             VARCHAR(255) NOT NULL,
  description      TEXT,
  duration_minutes INTEGER NOT NULL,
  price            DECIMAL(10,2),
  currency         VARCHAR(3) DEFAULT 'COP',
  images           TEXT[],
  is_active        BOOLEAN DEFAULT true,
  created_at       TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS business_hours (
  id          UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  store_id    UUID NOT NULL REFERENCES stores(id) ON DELETE CASCADE,
  day_of_week INTEGER NOT NULL CHECK (day_of_week BETWEEN 0 AND 6),
  open_time   TIME NOT NULL,
  close_time  TIME NOT NULL,
  is_open     BOOLEAN DEFAULT true,
  UNIQUE(store_id, day_of_week)
);

CREATE TABLE IF NOT EXISTS appointments (
  id               UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  client_id        UUID NOT NULL REFERENCES users(id),
  service_id       UUID NOT NULL REFERENCES services(id),
  store_id         UUID NOT NULL REFERENCES stores(id),
  start_time       TIMESTAMPTZ NOT NULL,
  end_time         TIMESTAMPTZ NOT NULL,
  status           VARCHAR(20) DEFAULT 'pending'
                   CHECK (status IN ('pending','confirmed','cancelled','completed','rescheduled')),
  notes            TEXT,
  cancel_reason    TEXT,
  allow_reschedule BOOLEAN DEFAULT true,
  created_at       TIMESTAMPTZ DEFAULT NOW(),
  updated_at       TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS reviews (
  id             UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  appointment_id UUID UNIQUE NOT NULL REFERENCES appointments(id),
  client_id      UUID NOT NULL REFERENCES users(id),
  store_id       UUID NOT NULL REFERENCES stores(id),
  rating         INTEGER NOT NULL CHECK (rating BETWEEN 1 AND 5),
  comment        TEXT,
  created_at     TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_appointments_store_time ON appointments(store_id, start_time);
CREATE INDEX IF NOT EXISTS idx_appointments_client ON appointments(client_id);
CREATE INDEX IF NOT EXISTS idx_stores_category ON stores(category);
CREATE INDEX IF NOT EXISTS idx_stores_location ON stores(lat, lon);
CREATE INDEX IF NOT EXISTS idx_stores_active ON stores(is_active);
SQL
Reemplaza TU_DB_PASSWORD con la contraseña que pusiste en el Paso 1.
Reemplaza TU_DB_ENDPOINT con el valor de DatabaseEndpoint del Output de CloudFormation.
Si termina sin errores verás mensajes como CREATE TABLE, CREATE INDEX, etc. Las tablas están listas.

7 Verificar que todo funciona

Consola AWS

  1. Abre tu navegador y ve a: http://TU_ELASTIC_IP
    (reemplaza con la IP del Output del Paso 1)
  2. Deberías ver la página de inicio de Nexo.
  3. Para verificar que el backend responde, abre: http://TU_ELASTIC_IP/api/health
    Debe responder: {"status":"ok"}

¿Algo no funciona? Cómo ver los logs

  1. En la consola AWS busca CloudWatch.
  2. Ve a Log groups.
  3. Abre el grupo /ecs/nexo.
  4. Ahí verás los logs separados por backend/ y frontend/.

(Opcional) Registrar el usuario admin

La app arranca sin usuarios. Crea el primer admin repitiendo el Paso 6.1 para ejecutar el seed:

node /app/src/scripts/seed.js

⚠ Destruir todo (cuando ya no lo necesites)

Consola AWS   Terminal

Esto elimina TODOS los recursos y datos. Es irreversible.
Haz un backup de la DB si necesitas los datos antes de borrar.

Paso A — Vaciar los repositorios ECR

CloudFormation no puede borrar un repositorio ECR si tiene imágenes adentro. Primero vacíalos desde la consola:

  1. En la consola AWS busca ECR (Elastic Container Registry).
  2. Haz clic en el repositorio nexo-backend.
  3. Selecciona todas las imágenes (checkbox arriba) → "Delete".
  4. Repite para el repositorio nexo-frontend.

Paso B — Eliminar el stack de CloudFormation

  1. Ve a CloudFormation en la consola AWS.
  2. Selecciona el stack nexo-prod.
  3. Haz clic en "Delete".
  4. Confirma con "Delete stack".
Tardará unos minutos. Cuando desaparezca de la lista, todo ha sido eliminado: VPC, EC2, RDS, ECS, ECR, IP — todo. Tu cuenta queda limpia.
